# FlamePanel · Issue 执行总纲

## 0. 轮次预算（硬约束：单会话 ≈300 轮）

| 阶段 | 上限 | 到点动作 |
|---|---|---|
| 领单（读 AGENTS / Skill / 任务单 / 指引文件） | 30 | 还没读完 → 说明任务单缺路径，停 |
| 实现 | 120 | 每写完一个文件 `cargo check` / `vitest run <spec>` |
| 门禁修复 | 60 | 同一报错 3 轮未消 → 回滚该改动，记「未解决项」 |
| 收尾 | 20 | **第 250 轮无论进度开始收尾** |

## 1. 领单（按序，≤30 轮）

1. `AGENTS.md` 已加载；读任务单全文，确认四项：目标 / 实现指引（读+写清单）/ 禁改 / 验收。
2. **按「读」清单的顺序与行段读文件**：`grep -n "<符号>" <file>` 定位 → `sed -n 'A,Bp'` 读 ±40 行。禁止 `cat` 千行文件（`sqlite.rs` 6000 行、`db.rs` / `permissions.rs` 等千行文件；`entity/`、`app_store_service/` 已按域拆分，也先 grep 定位）。
3. 按任务类型加载对应 Skill（AGENTS.md §4 路由表）。
4. 在 Issue 评论一条计划：
   ```
   计划：新增 <文件…>；修改 <文件…>；新增测试 N 个。
   不确定点：<有则列，无则写"无">
   ```
   有不确定点 → **等回复**再动手（只问一次，把所有问题列全）。

## 2. 实现纪律

- **模仿优先**：任务单的「参考实现」是结构模板——复制其字段顺序 / 错误映射 / 测试组织，再改业务逻辑。
- **只做任务单的事**：范围外问题写进 PR「后续建议」，不改。
- 任务单与代码现状冲突（路径不存在 / 签名已变）→ 评论指出，**以代码为准**继续，不发明结构。
- 不新增依赖、不 `#[allow]`、不 `as any`、不 `#[ignore]`、不放宽断言。
- 每个功能点完成即局部测试：`cargo test -p flame-kernel <关键字>` / `npx vitest run <path>`。

## 3. 止损

同一编译错误 / 测试失败 **3 轮未解决**：
1. `git checkout -- <该文件>` 回滚到上一个绿状态；
2. 换参考实现里的写法重来一次；
3. 仍不行 → 记入 PR「未解决项」（做到哪、报错原文、已试方案），继续其他部分。

## 4. 收尾（第 250 轮或完成，先到者为准）

1. 全量门禁（AGENTS.md §2）；
2. `git diff --stat` 对照禁改清单；
3. API / 表变更 → Doc/02 / Doc/03 加行，`CHANGELOG.md` 顶部加一段（≤10 行）；
4. 提交：`类型: 描述 (Ref: #n)`，中文；分支 `feat|fix|refactor|docs/<n>-<slug>`；
5. PR 描述：

```markdown
## 关联 Issue
Closes #<n>

## 变更清单
- `path/file.rs`：一行说明
- …

## 实现说明
<2–5 句：关键取舍；与任务单的偏差及原因>

## 测试结果
- `cargo test --all`：<N> passed（新增 <k>）
- `npm run test:unit`：<N> passed（若涉前端）
- 手动验证：<按验收标准逐条贴命令与输出>

## 后续建议
- 范围外发现：…
- 未解决项：…（无则写"无"）

## 收尾自查
1. diff 中有无禁改文件？<无 / 有并说明>
2. 每个新端点是否有 PermissionRule + 403 测试？<是 / 不涉及>
3. 迁移重复执行是否安全？<是 / 不涉及>
4. 非测试代码有无新增 `unwrap()`？<无 / 有并说明>

Ref: #<n>
```

任何验收项未达成 → 不发 PR，先评论说明阻塞。
