# 38 · R-01B 专用恢复探针与 HTTP 验收

> 用户在 R-01 离线首片后确认“继续”。本片实现可选的迁移 / HTTP 验证，不启动生产 `FlameKernel`，不改变云原生构建或发布流程。

## 1. 启动副作用审查与设计决策

不能把生产内核的“正常启动”直接用于恢复试验：`lib.rs` 的服务装配与监督任务包含 app-store/settings seed、WAF reload/sync、scheduled-task tick、backup-job tick、证书续签、自动备份、指标、清理、节点扫描、Outbox 和通知事件处理；`FlameKernel::run` 还恢复任务状态、补初始化状态并加载访问策略。即使最终只访问 `/health`，也不能据此证明没有触发其他动作。

**决策：独立入口，而不是在完整服务装配后打一个暂停标志。**

- 新增专用二进制 `fp-restore-probe`，由 Cargo 现有 bin 自动发现机制编译；不改 manifest、默认生产入口或打包脚本。
- 只复用 SQLite `run_migrations`、`seed_rbac` 与既有常量时间比较函数；只装配两个固定的 Axum 只读 HTTP 路由。
- 不构造 `FlameKernel` / `Services` / `RepoFactory`，不读取 `AppConfig`、JWT 文件、凭据密钥、环境中的面板配置或备份内的任务执行策略。
- 没有 shell、CommandRunner、Docker/Agent/SMTP/LLM 客户端、插件实例、生产 API 或 WebSocket 路由。

这是**按装配边界避免业务副作用**，不是 Linux network namespace、容器、seccomp 或对任意恶意二进制的操作系统沙箱。仅使用可信备份和本项目构建的可信探针。完整生产内核与后台服务启动仍未验收。

## 2. 执行流程

在 Doc/37 的 6 个离线阶段后，显式指定 `--probe-bin` 才运行新增 `probe` 阶段；默认仍为离线模式。

1. 驱动启动自有进程组，以隔离工作目录为 cwd；清空继承环境，仅提供 PATH / LANG / TMPDIR。
2. 每轮生成 32 字节随机秘密，以 stdin 匿名管道传递 64 位 hex token；不放进 argv、环境、报告或日志。
3. 探针只读打开源，拒绝符号链接 / 非普通文件 / 活库旁文件，限 512 MiB；在 cwd 新建随机 `.probe-*` 目录，把源复制成 0600 私有文件。
4. integrity_check、拒绝 trigger / view / virtual table、检查核心表，再在**副本**执行现有迁移与 RBAC seed，随后复查完整性。
5. 关闭写连接池，重开只读池，然后才绑定 `127.0.0.1:0`。随机端口由操作系统分配，不接受 host / port 覆盖。
6. stdout 只发送固定协议 `flamepanel/restore-probe/v1`、端口和 migrated 标记；不输出 token、路径或数据值。
7. 驱动执行 HTTP 鉴权、路由拒绝和聚合读取检查。结束时 SIGTERM 触发关闭连接池与删除副本；等待 5 秒仍不退出则强制终止并将本次判为失败。
8. 探针在接收 token、复制源之后，为迁移 / HTTP 阶段设置 1–300 秒期限；到期触发优雅关闭。驱动的截止时间覆盖等待就绪与 HTTP 验证，另有 5 秒停止等待；异常分支同样回收自有子进程，之后清理工作目录。单独运行探针的 stdin / 文件复制及优雅关闭不是硬实时上限，应使用外层驱动。

迁移可能改变 / 清理历史设置或补种角色数据，这正是为何必须在额外副本上执行；输入快照和上一个离线恢复副本不被迁移修改。

SIGKILL / 宕机不能保证探针自行运行析构；外层驱动仍会在可捕获失败时清理私有目录。如果整个驱动也被强杀，需按 Doc/37 检查残留文件。没有安全擦除或硬实时 / 磁盘配额承诺。

## 3. 使用

在 CNB 云原生开发环境的独立目录构建，不使用普通云构建流水线：

```bash
cargo build --locked -p flame-kernel --no-default-features --features sqlite --bin fp-restore-probe

python3 scripts/restore-drill/drill.py \
  --backup /secure/export/flamepanel-snapshot.db \
  --probe-bin "$PWD/target/debug/fp-restore-probe" \
  --out ./new-unique-probe-report \
  --timeout 120
```

- 二进制必须名为 `fp-restore-probe`，但文件名校验不代表密码学认证；部署时应核对构建来源与摘要。**不能把生产 `flame-kernel`、其他程序或不可信文件传给此参数。**
- Linux / Unix + SQLite feature 为有效组合；缺 SQLite 或非 Unix 构建会明确失败，不退回生产启动。
- 本片不改安装 / 发布脚本；探针需要按上述命令单独构建，不假设现有发布包已经包含它。
- 探针当前上限为 512 MiB，即使离线 `--max-bytes` 更大也不放宽探针上限。
- 不设置生产 OP_*、数据库地址或秘密环境变量；它们不参与探针配置。

## 4. HTTP 契约（非生产 API）

| 路径 / 方法 | 行为 |
| --- | --- |
| `GET /health` | 带正确 Bearer token 返回 ready、固定 mode、`production_kernel=false` |
| `GET /summary` | 带正确 token 返回 users / websites / scheduled_tasks 的行数，不返回数据行或设置值 |
| 无 token / 错 token / 仅 query token | 401 |
| 有 token 的 `POST /summary` | 405 |
| 有 token 的生产 `/api/*`、`/ws/*` 等未注册路径 | 404 |

只有 localhost 监听，没有 CORS 开放、会话、登录、写接口、任意 SQL 或自定义路径参数。聚合查询有 2 秒等待限制，SQL 错误不返回内部详情。

这是一套短时探针凭据，不是从备份中恢复的生产身份体系：**不证明生产 JWT、用户密码、2FA 或 RBAC 拒绝路径可用**。生产路由 / 权限表 / OpenAPI 没有改变；上述端点不应添加到生产 API 文档或客户端类型中。

## 5. 报告与验收

保留 `schema=flamepanel/restore-drill/v1`，新增可选阶段及字段：

- `scope=sqlite-with-dedicated-probe`：请求了专用探针；不指定参数时维持离线 scope。
- `migration_verified` / `probe_http_verified`：仅整个探针阶段成功、正常停止后变为 true。
- `probe`：包含 migration/auth/write-route 检查、三个表的行数、探针耗时、正常停止标记。
- `kernel_started=false`：始终表示生产内核未启动。
- `production_rto_seconds=null`、`rpo_seconds=null`：继续未知。

失败阶段仍为 FAIL，未运行阶段保持 NOT_RUN；探针错误只记录固定错误码，不保存原始异常或响应。默认离线模式的原 25 项测试必须继续通过。

新增 `flame-kernel/tests/restore_probe.rs` 调用真实构建产物运行 `probe_contracts.py`：

- 旧 core schema + 启用状态、过期 next_run_at 的计划任务；副本迁移 / seed / HTTP 通过，任务内容不执行。
- 源库字节、旧列集合和会被迁移清理的历史设置保持不变。
- 未授权、错 token、query token、写方法、生产 API / WebSocket 路由被拒绝。
- 直接启动探针时即使携带 OP_HOST / OP_PORT / OP_DATABASE_URL / OP_FILE_ROOT，也不改变探针监听与数据位置。
- TTL 自动退出、主动停止、失败迁移、活动 schema、坏 token、缺失源、错误二进制名，均验证清理或拒绝。

```bash
cargo test --locked -p flame-kernel --no-default-features --features sqlite --test restore_probe
python3 scripts/restore-drill/probe_contracts.py "$PWD/target/debug/fp-restore-probe"
bash scripts/ci-local.sh --keep-going all
```

可选 `FP_PROBE_EVIDENCE=/root/new-unique-evidence-dir` 导出合成场景的报告。目录必须不存在；不要把此变量持续带入重复完整门禁。
