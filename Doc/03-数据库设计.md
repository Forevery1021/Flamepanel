# 03 · 数据库设计

> FlamePanel SQLite 表结构、字段说明、实体关系与迁移机制

## 1. 概览

- **数据库引擎**：SQLite（`sqlx` 0.9 + `runtime-tokio`）
- **双模式**：InMemory（默认开发/测试）与 SQLite（生产）
- **迁移机制**：`infrastructure/sqlite.rs` 的 `run_migrations()` 在启动时自动执行 `CREATE TABLE IF NOT EXISTS`，幂等无副作用
- **时区**：`created_at` / `updated_at` 存储为 UTC 时间字符串

### 1.1 存储模式切换

| 场景 | `OP_DATABASE_URL` | 存储 |
|------|-------------------|------|
| 开发/测试默认 | `sqlite://data/app.db` | InMemory |
| 生产（install.sh） | `sqlite:/opt/flamepanel/data/flamepanel.db?mode=rwc` | SQLite |
| 手动指定 | 任意非默认 URL | SQLite |

> `main.rs` 判断：`config.database.url != "sqlite://data/app.db"` 时启用 SQLite。

### 3.6 `permissions` — 权限定义

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PK AUTOINCREMENT | 主键 |
| resource | TEXT | NOT NULL | 资源（user/node/docker/…） |
| action | TEXT | NOT NULL | 动作（read/create/update/delete/…） |
| description | TEXT | NOT NULL DEFAULT '' | 描述 |
| — | — | UNIQUE(resource, action) | 业务主键（`idx_permissions_resource_action`）：种子 upsert 的冲突目标，同时阻止同资源同动作重复定义 |

> **索引迁移**：唯一索引由 `run_migrations()` 幂等补建；补建前先做一次幂等去重
> （保留最小 id 行，先清理指向被裁行的映射与孤儿映射，再裁权限行，避免撞主键/外键），
> 覆盖曾手工改库的实例。

### 3.7 `roles` — 角色

| 字段 | 类型 | 约束 | 说明 |

| name | TEXT | NOT NULL UNIQUE | 角色名 |
| description | TEXT | NOT NULL DEFAULT '' | 描述 |

### 3.8 `role_permissions` — 角色-权限关联

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| role_id | INTEGER | NOT NULL, PK 复合 | 角色 ID |
| permission_id | INTEGER | NOT NULL, PK 复合 | 权限 ID |
| 外键 | — | role_id → roles(id), permission_id → permissions(id) | — |

> **种子（SQLite 模式）**：三张 RBAC 表的**唯一写入路径**是启动期
> `infrastructure/sqlite.rs::seed_rbac()`（由 `RepoFactory::new_sqlite()` 在迁移后同步调用）。
> `permissions` / `roles` 走 upsert（只更新描述）；`role_permissions` **仅在角色尚无任何映射时**
> 写入默认集合——已有映射（经角色管理定制的授权）保持不动。详见 [07-权限体系设计 §5.1](./07-权限体系设计.md)。
> 历史缺陷：该函数曾缺失，导致 SQLite 模式三表恒空、admin 全站 403（见 CHANGELOG）。

### 3.14 `app_sources` — 远程应用源（M-A Issue 1.1）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PK AUTOINCREMENT | 主键 |
| name | TEXT | NOT NULL | 源显示名称 |
| source_type | TEXT | NOT NULL | 源类型（git / http） |
| url | TEXT | NOT NULL UNIQUE | 源地址（重复添加被拒绝） |
| enabled | INTEGER | NOT NULL DEFAULT 1 | 是否启用 |
| public_key | TEXT | 可空 | Ed25519 公钥（应用包验签，Doc/20 §4.2） |
| last_synced_at | DATETIME | 可空 | 最近一次索引同步时刻 |
| created_at / updated_at | TEXT | NOT NULL | 创建/更新时间 |

**索引**：`idx_app_sources_enabled ON app_sources(enabled)`（启用状态过滤）、`idx_app_packages_source ON app_packages(source)`（按源过滤应用列表）

> 远程源同步（M-A Issue 1.2）：索引同步经 `RemoteAppSource` 端口拉取后以 `create_many` 幂等落库（已存在 key 跳过），成功后触达 `last_synced_at`；同步任务记录复用统一任务中心 `tasks` 表。
>
> 包签名验签（M-A Issue 1.3）：源配置 `public_key` 后，同步阶段（git 源包体就地验证）与安装阶段（按包来源 url 关联源）强制校验包根 `signature.sig`（Ed25519 对包内容摘要的签名，base64）。settings `app_signature_policy=required` 时未配公钥的源拒绝同步/安装其远程包。

### 3.14a `backup_accounts` — 备份账号（M-A 收尾 Stage 1 · Doc/20 §6.5）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PK AUTOINCREMENT | 主键 |
| name | TEXT | NOT NULL UNIQUE | 账号显示名称（重复命名被拒绝） |
| account_type | TEXT | NOT NULL | 账号类型（s3 / sftp / local） |
| config_json | TEXT | NOT NULL DEFAULT '{}' | 后端连接配置（JSON，由对应 BackupBackend 实现自解析）。**落库前经 AES-256-GCM 加密**为 `enc:v1:` 前缀密文（空 `{}` 不加密） |
| enabled | INTEGER | NOT NULL DEFAULT 1 | 是否启用 |
| last_test_status | TEXT | 可空 | 最近一次连通性测试：ok / failed |
| last_test_at | DATETIME | 可空 | 最近一次连通性测试时刻 |
| created_at / updated_at | TEXT | NOT NULL | 创建/更新时间 |

**索引**：`idx_backup_accounts_enabled ON backup_accounts(enabled)`（启用状态过滤）

> Stage 1 交付数据层与账号 CRUD/连通性测试登记（`/api/backup-accounts`）。
> Stage 2（已落地）：`BackupBackend` trait 三实现——`LocalBackend`（本地目录）/ `SftpBackend`（ssh2，密码或私钥）/ `S3Backend`（object_store，S3 兼容：AWS S3 / MinIO / OSS / COS / R2）；连通性测试升级为真实探测（连接 + 认证 + 写探针）；备份编排按账号路由（upload/download/list/delete 远端对象，REST 见 Doc/02 §16.1）。
> 凭据加密（Doc/20 §6.5 收尾）：`config_json` 含 SFTP 密码 / S3 secretKey 等敏感字段，写库前统一 AES-256-GCM 加密（HKDF-SHA256 派生密钥，主密钥持久化于 `data/secret_encryption.key`，首次启动生成，权限 0600）；读取时透明解密，**历史明文行静默兼容**（首次编辑后写回即完成迁移）。密钥文件丢失则历史密文不可解，需重建备份账号。

| enabled | INTEGER | NOT NULL DEFAULT 1 | 是否启用 |

> Stage 3 交付：计划备份任务 CRUD + 调度 tick（后台 Supervisor 每 30s，同任务防重叠）+
> 执行编排（panel 复用 VACUUM INTO 快照；app 目录 tar.gz 打包上传后清理本地临时包）+
> 远端保留策略 + 云端恢复（`/api/backup-jobs/restore-cloud`）+
> Outbox `BackupSucceeded`/`BackupFailed` 通知。REST 见 Doc/02 §16.2。

## 5. 数据初始化流程

```mermaid
sequenceDiagram
    participant M as main.rs
    participant F as RepoFactory
    participant S as FlameKernel
    participant DB as SQLite

    M->>F: new_sqlite(url)
    F->>DB: 连接 + run_migrations() 建表
    F->>DB: seed_rbac() 权限/角色/角色权限种子（同步，失败即启动失败）
    M->>S: new_with_backend(config, factory)
    S->>S: 异步 seed_builtin_apps() + restore_wasm_plugins()
    S->>DB: 异步 seed_default_settings()（upsert，不覆盖用户配置）
    S->>DB: 无用户时创建 admin（无人值守）／等待 Setup 向导
    S->>S: 启动 HTTP 服务
```

## 6. 迁移与备份

### 6.1 迁移

- 所有迁移均为 `CREATE TABLE IF NOT EXISTS`，在 `run_migrations()` 中按序执行。
- 新增字段/表时：修改 `run_migrations()`，追加 `ALTER TABLE ... ADD COLUMN` 或新 `CREATE TABLE`（注意幂等）。
- 迁移在启动时自动执行，无需手动 SQL。
- **种子数据**：RBAC 三表（`permissions` / `roles` / `role_permissions`）由
  `seed_rbac()` 在迁移后**同步**种子（失败即启动失败——RBAC 未就绪时面板整体 403）；
  默认设置由 `seed_default_settings()` 异步 upsert（不覆盖用户已改配置）。

### 6.2 备份

```bash
# 停服后直接复制（推荐 SQLite 一致性）
sqlite3 /opt/flamepanel/data/flamepanel.db ".backup '/backup/flamepanel-$(date +%Y%m%d).db'"

# 或运行中复制（简单场景）
cp /opt/flamepanel/data/flamepanel.db /backup/flamepanel-$(date +%Y%m%d).db
```

### 6.3 常见运维

```bash
# 查看表结构
sqlite3 data/app.db ".schema users"

# 清空重来（删除数据库后重启自动重建）
rm -f data/app.db
```

> 开发模式（InMemory）下数据不持久化，重启即清空，适合测试。
