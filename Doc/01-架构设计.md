# 01 · 核心架构与代码导航

> 先理解启动、依赖注入与安全边界，再进入具体业务。本文不复制端点清单、依赖版本和历史交付记录；它们分别由 OpenAPI、锁文件与 CHANGELOG 维护。

## 1. 系统边界

```text
浏览器：Vue 页面 → composables → HTTP / WebSocket
                                  │
原生部署：nginx → flame-kernel（非 root 的面板进程）
                                  ├─ SQLite：业务状态与审计
                                  ├─ Docker / Web 引擎 / 文件 / 运行时适配器
                                  ├─ flamepanel-helper：本机 root 助手，Unix socket + 白名单
                                  └─ flamepanel-agent：远端节点，HTTP 或可选 Edge 出站通道
```

- 面板是管理面，不替代 Docker、数据库或 Web 引擎本身。
- 上图描述原生安装；Docker 的用户、挂载与宿主机权限边界不同，见 [安全基线](./12-安全基线与兼容矩阵.md)。挂载 Docker socket 不等于低权限部署。
- `agent/` 已模块化，不是单文件程序；Edge、MCP、助手和 IaC 只读导出已有源码，不能继续按“尚未开发”排期。

## 2. 分层与启动链

设计方向：`api → application → domain ← infrastructure`。领域层可以使用序列化、时间和类型工具，但不应执行 I/O 或依赖具体基础设施。

| 层 / 入口 | 职责与源码                                                                                                                                             |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 程序入口  | [`main.rs`](../flame-kernel/src/main.rs)：CLI 分支、日志、配置、后端选择、启动内核                                                                     |
| 组合根    | [`lib.rs`](../flame-kernel/src/lib.rs)：`FlameKernel::new_with_backend`、`build_services`，集中创建并注入仓储、端口与服务                              |
| API       | [`api/routes.rs`](../flame-kernel/src/api/routes.rs) 聚合路由；handler 转换输入、调用 Service、返回统一 `AppError`                                     |
| 应用层    | [`application/`](../flame-kernel/src/application/) 编排用例、任务和领域事件；应用商店等大域已经拆为子模块                                              |
| 领域层    | [`domain/entity/`](../flame-kernel/src/domain/entity/)、[`repository.rs`](../flame-kernel/src/domain/repository.rs)：实体、仓储接口与纯规则            |
| 基础设施  | [`infrastructure/factory.rs`](../flame-kernel/src/infrastructure/factory.rs)：`RepoFactory` 选择 InMemory / SQLite；具体实现负责数据库、进程和网络 I/O |

**当前实现并非零边界债务**：备份账号、证书、防火墙、体检等 Service 仍直接引用部分基础设施类型。新代码不得扩大这种耦合；现有边界调整应单独评审，见 [清理清单](./35-工程清理清单.md#4-架构与构建债务另行处理)。

### 2.1 持久化不是由 URL 猜测

- `main.rs` 读取 `config.database.backend`：默认 `sqlite`；显式 `OP_DATABASE_BACKEND=memory` 才使用内存后端。
- SQLite 工厂初始化迁移和 RBAC 种子，并使用读写双池；具体参数由 `RepoFactory::new_sqlite` 维护。
- `FlameKernel::new()` 是内存模式的便捷入口，不能据此推断生产默认配置。
- Docker 不可用时，Docker 仓储可以回退到模拟实现；**这不把 SQLite 业务存储切换成 InMemory**。

## 3. 必须守住的核心链条

### 3.1 HTTP、权限与契约

```text
请求 → Request-Id / tracing / 限流 → JWT + RBAC → handler → Service → Repository / Port
```

- 权限映射的单一来源是 [`api/permissions.rs`](../flame-kernel/src/api/permissions.rs)，首条匹配生效，未知受保护路由默认拒绝。
- 认证使用共享 JWT 实例、用户 / 角色服务与缓存失效机制；不得在每个 handler 重建一套认证逻辑。
- WebSocket 在首帧完成认证和通道权限检查，连接期间复核并支持带内续期，见 [`api/ws_auth.rs`](../flame-kernel/src/api/ws_auth.rs)。不得把 access token 放入 URL。
- HTTP 错误统一来自 [`core/error.rs`](../flame-kernel/src/core/error.rs)；内部错误链记录日志，不直接暴露客户端。
- OpenAPI 注解 → [`openapi.rs`](../flame-kernel/src/openapi.rs) → [`frontend/openapi.json`](../frontend/openapi.json) → [`Doc/api/`](./api/README.md) 与前端生成类型。`ToSchema` 文档 DTO 即使不被运行时实例化，也可能是有效契约代码。

### 3.2 命令、特权与秘密

- 外部命令通过领域端口 [`domain/execution_mode.rs`](../flame-kernel/src/domain/execution_mode.rs) 的 `SharedCommandRunner` 注入；实现位于 [`infrastructure/execution.rs`](../flame-kernel/src/infrastructure/execution.rs)。
- [`application/execution_mode.rs`](../flame-kernel/src/application/execution_mode.rs) 是兼容再导出，不是第二套实现。禁止为了“去重”删除兼容入口。
- 本机 Web 引擎的特权操作由 [`webserver/helper/`](../flame-kernel/src/webserver/helper/) 的协议、路径白名单和授权边界控制，不能改成面板任意 sudo。
- `SecretCipher` 定义于 [`utils/secret_box.rs`](../flame-kernel/src/utils/secret_box.rs)。备份 / DNS 服务保留历史明文兼容及密钥不可用时的现有降级分支；若要改变为 fail-closed，必须另立安全决策，不能在清理中悄悄改变行为。
- Agent 的命令白名单、文件沙箱和 token 校验是独立安全边界，不与面板的同名工具函数盲目合并。

### 3.3 任务与事件

- [`runtime/supervisor.rs`](../flame-kernel/src/runtime/supervisor.rs) 的 `TaskSupervisor` 管理后台任务、取消和关闭；长任务不占着 HTTP 请求等待完成。
- [`event/`](../flame-kernel/src/event/) 通过进程内广播解耦副作用；组合根连接通知和 Outbox 落库 / 重试任务。
- 广播与订阅落库不能直接视作“业务事务与 Outbox 原子提交”的保证。需要更强一致性的场景应独立设计，而不是更换文档措辞掩盖差异。

### 3.4 MetricsHub 与实时推送

- [`infrastructure/metrics.rs`](../flame-kernel/src/infrastructure/metrics.rs) 的 `MetricsHub` 统一采集、缓存与广播，避免各 WS 会话重复采集系统状态。
- 历史聚合由 [`application/metrics_history_service.rs`](../flame-kernel/src/application/metrics_history_service.rs) 完成，再通过仓储持久化；前端历史查询与实时流分开。
- [`api/ws_backpressure.rs`](../flame-kernel/src/api/ws_backpressure.rs) 处理慢消费者、重同步信号与指标。新增订阅者必须处理 lag / 关闭，不得无限堆积消息。

## 4. 前端与 Agent

### 4.1 前端：组装与业务逻辑分开

| 核心位置                                                                     | 职责                                                                                                 |
| ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| [`src/main.ts`](../frontend/src/main.ts)                                     | 安装 Pinia、Router、VueQuery、i18n、OpenVue 和服务 / 指令                                            |
| [`src/api/`](../frontend/src/api/)                                           | HTTP 客户端与生成契约，规范化错误                                                                    |
| [`useApiQuery.ts`](../frontend/src/composables/useApiQuery.ts)               | 服务端状态查询，与 [`useQueryCache.ts`](../frontend/src/composables/useQueryCache.ts) 的缓存约定配合 |
| [`useSharedWebSocket.ts`](../frontend/src/composables/useSharedWebSocket.ts) | 共享实时连接、重连与 resync                                                                          |
| [`components/ui/`](../frontend/src/components/ui/)                           | `Fp*` 组件边界；业务页不直接耦合底层组件库                                                           |
| [`ProjectView.vue`](../frontend/src/views/ProjectView.vue)                   | composables + 子组件的组装示例；查询、操作和展示分离                                                 |

页面测试应复现需要的生产插件：**每次 mount 使用新的 `createPinia()`**，测试结束自动卸载；不要靠全局 active Pinia、stub 掉全部真实子组件或屏蔽 `console.warn` 来隐藏缺装配。

### 4.2 Agent：保持轻量，不引入完整内核

[`agent/src/main.rs`](../agent/src/main.rs) 是组装入口；`config`、`heartbeat`、`server`、`executor`、`install_policy`、`files`、`pty`、`edge` 分别承担配置、注册 / 心跳、入站接口、执行策略、文件、终端和出站连接。

同类算法可能在两个进程独立出现。减少重复前先检查依赖成本、协议兼容、权限与平台语义；不能为共用一个小函数让 Agent 依赖完整面板。协议细节见 [Doc/23](./23-Agent节点通信协议.md)。

## 5. 能力裁剪与工具链

默认 features 为 `sqlite / docker / wasm / email`，实际依赖和组合以 [`flame-kernel/Cargo.toml`](../flame-kernel/Cargo.toml) 为准。

| 关闭能力 | 影响                                                           |
| -------- | -------------------------------------------------------------- |
| `sqlite` | 使用内存仓储，重启不保留业务数据                               |
| `docker` | 不编译 Docker 适配器；保留模拟仓储边界，不等于真实 Docker 操作 |
| `wasm`   | 保留插件元数据边界，WASM 执行不可用                            |
| `email`  | 不加载邮件渠道，不代表事件链被删除                             |

工程基线：[`rust-toolchain.toml`](../rust-toolchain.toml) 固定 **Rust 1.98.1**，workspace `rust-version` 声明同一受支持最低基线；edition 仍为 2021，`Cargo.lock` 不随清理升级。更旧编译器没有经本轮矩阵验证。

```bash
bash scripts/check-rust-toolchain.sh
bash scripts/ci-local.sh --keep-going all  # 在 CNB 云原生开发环境，不触发普通云构建
```

## 6. 修改时的最短路径

1. 找当前路由 / 调用方，再沿 Service → 领域端口 → 适配器追踪；参考现有测试，不按旧任务单猜文件名。
2. 组合根注入具体实现，保持接口与权限语义；新增字段检查生产和 `tests/common/mod.rs::setup_router`。
3. 修改契约时更新 OpenAPI / 生成物，修改持久化时验证幂等迁移和种子。
4. 先跑定点回归，再跑云原生开发环境完整门禁；性能、安全审计、跨架构发布验证另行记录，不能以单测通过替代。
5. 清理遵守 [Doc/35](./35-工程清理清单.md)：列证据、确认外部 / 动态引用、得到范围批准后再删除。
