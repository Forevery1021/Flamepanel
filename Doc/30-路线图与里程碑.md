# 30 · 维护路线与架构演进

> 路线图只保留当前方向和可验收切片；历史交付查 [CHANGELOG](../CHANGELOG.md)，详细历史计划查 [Doc/32](./32-v1.x执行计划.md)。有源码、门禁通过、真实系统验收和正式发布是四种不同状态。

## 1. 产品与当前工作边界

FlamePanel 是自托管 Linux 管理面：一个 Rust 内核、静态 Vue 前端、SQLite 状态存储和轻量 Agent。核心价值是复用宿主机已有软件，而不是重新造运行时。

**当前优先级：完成已授权的 R-01 恢复验证续片，保持工程基线稳定；其他未来产品功能不自动开工。**

用户于 2026-10-12 补充授权维护清理与后续规划；新增 [Doc/36 后续产品路线规划](./36-后续产品路线规划.md)，参考现代运维面板，以恢复验证、部署失败保护和节点可靠性为候选方向。规划不等于开工批准；已单独确认的 R-01 各片边界见 §7，其余候选及云原生构建 / 发布边界不自动放开。

- 先修测试装配，再固定工具链、整理核心架构文档。
- 死代码 / 重复逻辑必须先进入 [Doc/35 清理清单](./35-工程清理清单.md)，确认引用、兼容和风险后才处理。
- 不以路线图条目为自动开发授权；下一项功能需用户另行确认。

## 5. 非目标

- 本轮不新增 API、UI、MCP 工具、导入 / 部署能力或后台业务任务。
- 不支持 Windows 面板端，不自研容器运行时，不在未经决策时引入 Kubernetes。
- 不为去重新增公共 crate、框架或未声明依赖；Agent 不依赖完整内核。
- 不通过删测试、降覆盖率 / 包体预算、关闭 lint 或吞告警完成清理。
- 用户要求零云构建时，不以普通 push、PR、tag 或 build-start 做验证；授权推送同时使用 `[skip ci]` 与 `-o ci.skip`，不创建 PR / tag。

## 6. 版本与发布

- 产品版本以 Cargo / 前端 manifest 和实际 tag / Release 为准；不根据路线图标题推断已经发布。
- Rust 工程基线见 [`rust-toolchain.toml`](../rust-toolchain.toml)：**1.98.1**；这不是产品版本。
- 日常验证在 CNB 云原生开发环境执行 `bash scripts/ci-local.sh --keep-going all`。完整门禁不代替性能压测、Rust 安全审计、跨架构 release、真实安装 / 多节点验收。
- 发布需另行授权，按 [Doc/31 §8](./31-开发流程.md#8-发布) 和 [Doc/10](./10-部署运维指南.md) 执行；本轮不触发发布。

R-01D 续片（2026-10-14 用户确认）：[显式授权的恢复主密钥匹配验证](./40-恢复主密钥匹配验证.md)。独立离线命令在明确授权后读取操作员暂存的主密钥，复用现有 SecretCipher，对固定范围密文做只读认证验证，不输出明文。R-01C 默认仍不读密钥；本轮开发只用合成材料，不启动生产内核、不新增生产 API/UI，不把匹配结果当作生产身份或完整恢复就绪。
