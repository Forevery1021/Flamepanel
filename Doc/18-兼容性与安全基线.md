# FlamePanel 兼容性与安全基线

> 对应 Master Handbook Phase A3（实机与安全基线）。本文档定义受支持的**操作系统兼容矩阵**与**安全验收清单**，作为生产信任与发布门禁的依据。

## 1. 目标

1. 明确 FlamePanel 在主流 Linux 发行版上的**支持级别**（完全支持 / 最佳努力 / 不支持）。
2. 提供**上线前安全检查表**，覆盖非 root、TLS、备份、WS 鉴权、Agent 令牌、路径穿越等否定用例。
3. 作为 CI 安全审计（`cargo audit` / `npm audit`）与发布门禁的配套说明。

## 2. 操作系统兼容矩阵

> 兼容性基于：`flame-kernel` 后端（Rust）+ `flame-agent`（Rust）+ 前端静态资源 + systemd / Docker 两种部署方式。

### 2.1 支持级别定义

| 级别 | 含义 |
|------|------|
| **完全支持** | CI 矩阵覆盖、安装脚本验证、故障在 24h 内响应 |
| **最佳努力（Best-effort）** | 未列入自动矩阵，但预期可用；仅社区反馈修复 |
| **不支持** | 已知缺依赖或内核特性不满足，不予承诺 |

### 2.2 兼容矩阵

| 发行版 | 版本 | 架构 | 支持级别 | 备注 |
|--------|------|------|----------|------|
| **Debian** | 12 (bookworm) | amd64 / arm64 | ✅ 完全支持 | 推荐默认 |
| **Debian** | 13 (trixie) | amd64 / arm64 | ✅ 完全支持 | 推荐默认 |
| **Ubuntu** | 22.04 LTS | amd64 / arm64 | ✅ 完全支持 | |
| **Ubuntu** | 24.04 LTS | amd64 / arm64 | ✅ 完全支持 | 推荐默认 |
| **Rocky Linux** | 9.x | amd64 / arm64 | 🟡 最佳努力 | RHEL 系代表 |
| **AlmaLinux** | 9.x | amd64 / arm64 | 🟡 最佳努力 | RHEL 系代表 |
| **CentOS Stream** | 9 | amd64 | 🟡 最佳努力 | 非 LTS，关注迁移 |
| **Alpine Linux** | 3.19+ | amd64 / arm64 | 🟡 最佳努力 | 依赖 musl 静态构建，需验证 |
| **其他 (Arch / Fedora / openSUSE)** | 滚动/新版本 | amd64 | 🟡 最佳努力 | 社区支持 |

> **判定标准**：安装脚本（`install.sh`）在目标系统从零到可用、`systemctl` 服务正常、Web UI 可登录、容器列表可读。

### 2.3 内核与运行环境要求

| 项 | 要求 |
|----|------|
| Linux 内核 | ≥ 5.10（兼容性最好）；≥ 4.18 为最低尽力 |
| systemd | ≥ 245（建议）；SysVinit 为 best-effort |
| Docker Engine | ≥ 20.10（可选，仅容器管理功能需要） |
| OpenSSL | ≥ 1.1.1（TLS 1.2+ 必须） |
| 内存 | ≥ 512MB（建议 1GB+） |
| 磁盘 | ≥ 1GB（不含镜像/数据卷） |

## 3. 安全验收清单（上线前）

> 每一项对应一个验收动作；**否定用例**表示"必须能安全失败"。

### 3.1 进程与权限

- [ ] 以**非 root** 用户运行 API 进程（`execution_mode=embedded` 时高危动作仍走 Agent）。
- [ ] API 进程**默认不挂载** `/var/run/docker.sock`；需要写容器时经 `flame-agent`。
- [ ] Agent 仅监听本机 Unix Socket（或节点 mTLS），不暴露到公网。
- [ ] 危险动作（Docker/包管理/防火墙/引擎 reload）**只**经 Agent 动作枚举，禁止拼 Shell。
- [ ] 原生数据库（MySQL/Redis）管理命令（`mysql`/`mysqladmin`/`redis-cli`/`redis-server`）经统一特权命令端口执行；其内部 `sh -c` 配置/卸载脚本为 **embedded-only**（agent 模式白名单不含 `sh -c`，天然拒绝）。

### 3.2 认证与传输

- [ ] 面板启用 **HTTPS**（`--tls` 或前置 Nginx TLS）。
- [ ] JWT 过期时间合理，改密/锁定策略生效。
- [ ] **WebSocket** 连接带鉴权（`/ws` 需 Bearer token）。
- [ ] 默认账户已改密码；初始密码强度校验。

### 3.3 数据与配置

- [ ] SQLite 采用 **WAL** 模式（`journal_mode=WAL`）。
- [ ] 站点/引擎配置写路径带 **resource_version**（OCC），冲突返回稳定 `CONFLICT`。
- [ ] 备份可恢复；恢复流程有文档与演练。
- [ ] 路径访问经过 `canonicalize` + 白名单根校验，**否定用例**：`../` 穿越返回 403/400。

### 3.4 依赖与供应链

- [ ] `cargo audit` 通过（高危 0，或已开 ticket 豁免）。
- [ ] `npm audit` 通过（高危 0，或已开 ticket 豁免）。
- [ ] Release 资产带 SHA256SUMS 校验。

### 3.5 否定用例样例

| 场景 | 预期 |
|------|------|
| 无 Docker Socket 时写容器 | 返回明确失败语义（非静默成功） |
| 并发双写同一站点/引擎 | 后写冲突，返回 `409 CONFLICT`，不静默覆盖 |
| `npx`/危险字符注入 Shell | 被动作白名单拒绝 |
| 路径 `../../etc/passwd` | 返回 403/400 |

> **命令面收敛（Phase A 收尾）**：面板内部只读探测已不再 spawn 外部命令——
> `OsInfo::detect_distro` 改标准库直读 `/etc/os-release`，`health` 磁盘探测改用
> `sysinfo::Disks`（替代 `df -k`）。`terminal`（交互式 shell）与 `scheduled_task`
> （用户自定义 cron 命令）本质是用户驱动的任意命令执行，属功能特性而非特权命令面，
> 不纳入白名单收敛。

## 4. CI 安全门禁

| 检查 | 命令 | 门禁 |
|------|------|------|
| Rust 依赖审计 | `cargo audit` | 高危=0（否则阻断） |
| 前端依赖审计 | `npm audit --audit-level=high` | 高危=0（否则阻断） |
| 静态检查 | `cargo clippy --all-targets -- -D warnings` | 0 warning |
| 单元/集成 | `cargo test --all` | 0 fail |
| 前端类型/构建 | `npm run typecheck && npm run build` | 0 error |
