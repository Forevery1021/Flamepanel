# 40 · R-01D 显式授权的恢复主密钥匹配验证

> 用户已确认实施本片：只读、离线、显式授权读取独立暂存的主密钥，不返回明文；开发验收仅用合成材料。不新增生产 API/UI，不启动生产内核。R-01 整体仍未验收。

## 1. 与已有工具分开

[Doc/39](./39-恢复资产与外部密钥清单.md) 的 `inventory.py` 继续只看资产元数据，`secret_contents_read=false`、`key_match_verified=false` 的默认契约完全不变。

本片新增独立 `keycheck.py` 与内部加密工作程序 `fp-restore-keycheck`：

- 只处理操作员准备的独立 SQLite 快照和暂存主密钥；没有远端下载参数。
- Python 驱动复用现有安全复制、只读 SQLite 和 descriptor-relative / no-follow 路径检查。
- Rust 工作程序只接受经匿名管道提供的有界请求，复用现有 `SecretCipher`；不接收文件路径、数据库地址、SQL 或配置环境。
- 不调用 `load_or_create_master_secret`，不生成、轮换或修复任何材料，不构造 `FlameKernel`、Services、调度器或外连客户端。
- 不是 OS 沙箱；仅使用可信备份和本项目构建的可信工作程序。文件名检查不等于二进制来源认证。

## 2. 构建与调用

在 CNB 云原生开发的独立目录构建，不用普通云构建：

```bash
cargo build --locked -p flame-kernel --no-default-features --features sqlite --bin fp-restore-keycheck

python3 scripts/restore-drill/keycheck.py \
  --backup /secure/staging/snapshot.db \
  --assets-root /secure/staging/assets \
  --key-path secret_encryption.key \
  --keycheck-bin "$PWD/target/debug/fp-restore-keycheck" \
  --allow-secret-read \
  --out /secure/reports/new-unique-keycheck
```

使用自定义 `CARGO_TARGET_DIR` 时相应调整工作程序路径。发布 / 安装脚本不变，不假设现有发布包包含该程序。

- **没有 `--allow-secret-read` 就拒绝操作**，不获取快照、不读取密钥。必须逐次由操作员明确授权，不能把资产盘点自动升级为秘密读取。
- 不提供 `--master-value`、环境变量或 URL 密钥输入；不要把秘密值放进命令行、manifest 或 shell 历史。
- `--assets-root` 为操作员准备的非符号链接私有目录，group / other 无权限、属主可读 / 遍历，通常 0700。不要直接指定生产服务目录。
- `--key-path` 是根内规范相对路径，拒绝绝对路径、空组件、`.`、`..`、反斜杠和控制字符；每级相对目录 fd 打开，拒绝符号链接。
- 密钥必须是单硬链接普通文件，属主可读、group / other 无权限，通常 0600 / 0400；不读取 FIFO / 设备或不安全资产。权限位不代替 UID、ACL、挂载与服务身份审核。
- 主密钥按现有持久化加载语义处理：UTF-8 解码后由 Rust `trim`，把剩余文本的字节交给原 `SecretCipher`。**不把文件内容再按 hex/base64 解码成另一把密钥**；协议里的 base64 仅用于管道传输。
- 缺失、空白、坏编码或错误材料不被重新生成 / 覆盖。输入快照和密钥文件保持不变。
- `--out` 必须不存在，父目录预先准备；目录 0700，JSON / Markdown 报告 0600，不覆盖既有报告。

默认快照上限 512 MiB、期限 120 秒；`--max-bytes` 不可超过 512 MiB，`--timeout` 不可超过 3600 秒。`--sha256` 可提供可信渠道的预期快照摘要；未提供时不能把实算摘要当作来源认证。

## 3. 固定扫描范围与限额

只对私有随机子目录内的额外副本执行 integrity / 核心 schema 检查和白名单只读 SQL；不开启扩展、不执行任务、不迁移 / seed。拒绝 trigger、view、virtual / shadow table；目标字段为生成 / 隐藏列时按覆盖缺口处理。

字段沿用 R-01C 的清单：

- `backup_accounts.config_json`
- `dns_provider_accounts.credentials_json`
- `user_two_factor.secret` / `pending_secret`
- `panel_settings.value`，且只选 `key='assistant.api_key'`

历史明文仅聚合计数，不作为匹配证据、不送工作程序。其他设置、路径、账号 ID 与任意调用方 SQL 不被读取返回。

仅 `enc:v1:` 可以交给原解密器验证。原 `SecretCipher.decrypt` 的历史明文 passthrough **不能**证明密钥匹配；驱动与工作程序均单独拒绝未知前缀 / 版本。

扫描先做聚合前检。缺表 / 列、非 TEXT 值、未知版本、预算不足均不跳过后声称成功，而是在读取密钥内容之前返回不确定。上限：主密钥文件 4 KiB；1024 条密文、单条 64 KiB、总密文 1 MiB；工作请求 2 MiB、响应 4 KiB。大于范围的部署须另行评审，不能挑选前若干条伪装完整匹配。

## 4. 秘密与子进程边界

- 只有明确授权、输入检查和完整扫描通过且存在可验证密文后才读取密钥。读取前后检查元数据，拒绝观察到的权限 / 大小 / 时点变化。
- 密钥以匿名 stdin 管道传给可信工作程序，不写临时文件、argv、环境、报告或日志。工作程序内的解密值立即丢弃，只返回认证成功 / 拒绝的聚合计数。
- 子进程 cwd 为私有工作目录，继承环境被清空，仅提供 PATH / LANG / TMPDIR；OP_*、JWT 和面板配置不参与计算。没有监听端口或生产服务启动。
- 输出协议必须精确匹配固定 schema / 字段 / 整数计数；多余字段、重复键、矛盾计数、过量输出或失败退出均拒绝。工作程序 stderr 不进入报告。
- 驱动设置整体期限并回收自有进程组；超时 / 中断清理副本。终止可能另需最多约 4 秒等待，文件系统 / 调度不是硬实时限额。
- SIGKILL / 宕机不能保证驱动析构；需按 Doc/37 检查私有残留目录。没有 RAM 锁定、交换区保护、内存零化或安全擦除承诺。

## 5. 报告语义

输出 `keycheck.json`（`flamepanel/recovery-keycheck/v1`）与 `keycheck.md`：

| 状态 | 含义 | 退出码 |
| --- | --- | --- |
| MATCHED_WITHIN_SCOPE | 固定范围完整扫描、有至少一条支持的密文，全部通过现有 AEAD 解密认证 | 0 |
| NOT_VERIFIED | 至少一条认证 / 解码失败；错误密钥与损坏密文可能不可区分 | 1 |
| INCONCLUSIVE | 无可验证密文、覆盖缺口、未知版本或预算不足，不读取密钥内容 | 1 |
| BLOCKED | 未授权、不安全输入、快照 / 工作程序错误、超时、中断或清理失败 | 1 |
| 报告不可用 | 参数或输出失败，可能有不完整报告；不回显传入值 | 2 |

- `key_match_verified=true` 只用于 `MATCHED_WITHIN_SCOPE`，严格限于已观测白名单密文；不是密钥来源、所有秘密或业务凭据可用性证明。
- `secret_contents_read` 保守记录是否尝试读取被声明的主密钥文件；读取失败也可能为 true。它不是“没有读取数据库内容”的声明。
- `restore_ready=false`、`production_auth_verified=false`、`kernel_started=false` 始终保留。没有真实生产 RTO / RPO 结果。
- 报告只包含固定范围、状态、计数、快照摘要与固定错误码，不含输入路径、密钥长度 / 指纹 / 内容、密文、解密值或原始异常。运维元数据仍需权限保护。
- 即使本片匹配成功，R-01C 盘点也不会自动改为 PASS；JWT、bootstrap、ACME、证书私钥、生产认证、业务数据与外部恢复仍须单独验证。

## 6. 回归与后续

```bash
python3 -m unittest discover -s scripts/restore-drill -v
cargo test --locked -p flame-kernel --no-default-features --features sqlite --bin fp-restore-keycheck
cargo test --locked -p flame-kernel --no-default-features --features sqlite --test restore_keycheck
bash scripts/ci-local.sh --keep-going all
```

Python 用例覆盖授权、路径 / 权限 / 链接 / 类型、扫描缺口与预算、协议拒绝、环境隔离、输出限额、超时 / SIGTERM、清理、脱敏与输入不变。纯 Python 的编排测试使用显式测试替身，不能替代真实加密验收。

Rust 集成使用真实迁移、真实 `SecretCipher`、实际编译的工作程序和 5 个已知字段验证：匹配、错误密钥、部分坏密文、未知版本、覆盖缺口、无授权、无生产副作用及报告脱敏。新 Python 用例由已有 `restore_drill` 集成自动发现，新 bin / Rust 集成由 Cargo 自动发现，不改 CI 入口或门槛。

仅定点运行时可选 `FP_KEYCHECK_EVIDENCE=/root/new-unique-evidence` 导出合成场景报告，不导出秘密；重复场景拒绝覆盖。完整门禁不得持续带入该变量。
