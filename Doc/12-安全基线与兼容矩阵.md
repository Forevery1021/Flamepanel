# FlamePanel 兼容性与安全基线

> 对应 Master Handbook Phase A3（实机与安全基线）。本文档定义受支持的**操作系统兼容矩阵**与**安全验收清单**，作为生产信任与发布门禁的依据。

## 1. 目标

1. 明确 FlamePanel 在主流 Linux 发行版上的**支持级别**（完全支持 / 最佳努力 / 不支持）。
2. 提供**上线前安全检查表**，覆盖非 root、TLS、备份、WS 鉴权、Agent 令牌、路径穿越等否定用例。
3. 作为 CI 安全审计（`cargo audit` / `npm audit`）与发布门禁的配套说明。

## 2. 操作系统兼容矩阵

> 兼容性基于：`flame-kernel` 后端（Rust）+ `flame-agent`（Rust）+ 前端静态资源 + systemd / Docker 两种部署方式。

### 2.1 支持级别定义

| 级别 | 含义 |
|------|------|
| **完全支持** | CI 矩阵覆盖、安装脚本验证、故障在 24h 内响应 |
| **最佳努力（Best-effort）** | 未列入自动矩阵，但预期可用；仅社区反馈修复 |
| **不支持** | 已知缺依赖或内核特性不满足，不予承诺 |

### 2.2 兼容矩阵

| 发行版 | 版本 | 架构 | 支持级别 | 备注 |
|--------|------|------|----------|------|
| **Debian** | 12 (bookworm) / 13 (trixie) | amd64 / arm64 | ✅ Tier 1 | 推荐默认；五引擎 / 数据库 / 运行时全链路 |
| **Ubuntu** | 22.04 / 24.04 LTS | amd64 / arm64 | ✅ Tier 1 | 推荐默认 |
| **Rocky / AlmaLinux / RHEL / Oracle Linux** | 9.x | amd64 / arm64 | 🟡 Tier 2 | 安装脚本自动处理 SELinux（`httpd_can_network_connect` + 文件标签）与 firewalld；原生 MySQL / PG 有限制（Doc/33 P-3） |
| **CentOS Stream / Fedora** | 9 / 40+ | amd64 | 🟡 Tier 2 | 同上；非 LTS |
| **openEuler / Anolis / OpenCloudOS / Kylin；UOS / Deepin** | 当前版本 | amd64 / arm64 | 🟡 Tier 2（未真机） | 按 os-release `ID_LIKE` 归入 RHEL / Debian 族 |
| **openSUSE Leap / Tumbleweed** | 15.6+ / 滚动 | amd64 | 🟠 Tier 3 | 面板与 Nginx / Apache / Caddy 可用；OLS 无官方包；Redis 仅模板单元 |
| **Arch / Manjaro** | 滚动 | amd64 | 🟠 Tier 3 | 安装脚本自动为 nginx 主配置补 include（卸载回滚）；官方仓库 Redis 已由 Valkey 取代 |
| **Alpine Linux** | 3.19+ | amd64 / arm64 | 🐳 仅 Docker | 默认 OpenRC 无 systemd，`install.sh` 启动即报错；请用 Docker Compose |

> **级别定义（Doc/33 §4）**：Tier 1 = 安装脚本 + 原生功能全链路验证；Tier 2 = 安装与核心功能可用，部分原生软件有已知限制；Tier 3 = 面板可安装运行，原生软件需手工或不支持。
> **架构**：预编译包仅 amd64 / arm64，其它架构需 `cargo build --release` 后本地安装（脚本会提示）。
> **离线回归**：`scripts/tests/test_install_platform.py` 以 13 份真实 os-release 样本覆盖归族判定，并对生成的 nginx 配置执行真实 `nginx -t`。

> **判定标准**：安装脚本（`install.sh`）在目标系统从零到可用、`systemctl` 服务正常、Web UI 可登录、容器列表可读。

### 2.3 内核与运行环境要求

| 项 | 要求 |
|----|------|
| Linux 内核 | ≥ 5.10（兼容性最好）；≥ 4.18 为最低尽力 |
| systemd | ≥ 245（建议）；**必需**（OpenRC / SysVinit 不支持，请用 Docker） |
| Docker Engine | ≥ 20.10（可选，仅容器管理功能需要） |
| OpenSSL | ≥ 1.1.1（TLS 1.2+ 必须） |
| 内存 | ≥ 512MB（建议 1GB+） |
| 磁盘 | ≥ 1GB（不含镜像/数据卷） |

## 3. 安全验收清单（上线前）

> 每一项对应一个验收动作；**否定用例**表示"必须能安全失败"。

### 3.1 进程与权限

- [ ] 以**非 root** 用户运行 API 进程（`execution_mode=embedded` 时高危动作仍走 Agent）。
- [ ] API 进程**默认不挂载** `/var/run/docker.sock`；需要写容器时经 `flame-agent`。
- [ ] Agent 仅监听本机 Unix Socket（或节点 mTLS），不暴露到公网。
- [ ] 危险动作（Docker/包管理/防火墙/引擎 reload）**只**经 Agent 动作枚举，禁止拼 Shell。
- [ ] 原生数据库（MySQL / Redis / PostgreSQL / MongoDB）管理命令经统一特权命令端口执行；agent 模式下 `sh -c` 只放行两段内核常量脚本（逐字节比对 + 位置参数校验，目标文件限数据库配置清单）、`sed` 只放行端口改写模板（Doc/23 「数据库 / 运行时安装的逐项白名单」）。否定用例：`sh -c id`、改动过一个字符的常量脚本、`flame-append` 指向 `/etc/sudoers`、多行内容注入 Redis 配置都必须被拒。

### 3.2 认证与传输

- [ ] 面板启用 **HTTPS**（`--tls` 或前置 Nginx TLS）。
- [x] **CSP 等安全响应头基线**（T0-5）：`Content-Security-Policy`（`script-src` 无
  `unsafe-inline`/`unsafe-eval`，仅白名单首屏脚本 sha256）+ `nosniff` / `X-Frame-Options` /
  `Referrer-Policy`，随 `install.sh` 与 `nginx.conf` 默认下发。验收：
  `curl -sI <面板>/ | grep -i content-security-policy` 有输出且浏览器控制台无 CSP 违规。
  护栏 `frontend/src/config/__tests__/csp.spec.ts`；说明见 [06 §6.1](./10-部署运维指南.md)。
- [ ] JWT 过期时间合理，改密/锁定策略生效。
- [x] **WebSocket** 连接带鉴权（首帧鉴权：`{"type":"auth","token":"<access_token>"}` + RBAC）。✅ R2
- [ ] 默认账户已改密码；初始密码强度校验。

### 3.3 数据与配置

- [ ] SQLite 采用 **WAL** 模式（`journal_mode=WAL`）。
- [ ] 站点/引擎配置写路径带 **resource_version**（OCC），冲突返回稳定 `CONFLICT`。
- [ ] 备份可恢复；恢复流程有文档与演练。
- [ ] 路径访问经过 `canonicalize` + 白名单根校验，**否定用例**：`../` 穿越返回 403/400。

### 3.4 依赖与供应链

- [ ] `cargo audit` 通过（高危 0，或已开 ticket 豁免）。
- [ ] `npm audit` 通过（高危 0，或已开 ticket 豁免）。
- [ ] Release 资产带 SHA256SUMS 校验。

### 3.5 否定用例样例

| 场景 | 预期 |
|------|------|
| 无 Docker Socket 时写容器 | 返回明确失败语义（非静默成功） |
| 并发双写同一站点/引擎 | 后写冲突，返回 `409 CONFLICT`，不静默覆盖 |
| `npx`/危险字符注入 Shell | 被动作白名单拒绝 |
| 路径 `../../etc/passwd` | 返回 403/400 |

> **命令面收敛（Phase A 收尾）**：面板内部只读探测已不再 spawn 外部命令——
> `OsInfo::detect_distro` 改标准库直读 `/etc/os-release`，`health` 磁盘探测改用
> `sysinfo::Disks`（替代 `df -k`）。`terminal`（交互式 shell）与 `scheduled_task`
> （用户自定义 cron 命令）本质是用户驱动的任意命令执行，属功能特性而非特权命令面，
> 不纳入白名单收敛。
>
> **节点远程终端（batch-13）**：经 Agent Edge 通道的交互式 shell 同属用户驱动的任意命令执行，
> 但它以 **Agent 身份**在节点上运行、绕过 `/action` 白名单，因此默认关闭：节点侧须显式设置
> `AGENT_TERMINAL=1`；面板侧要求 `terminal:execute` + `node:execute` 双权限，开 / 关写审计，
> 单节点并发 ≤ 8，token 失效 / 权限收回 / 空闲 10 分钟即断开。
>
> **项目守护 unit（batch-13）**：`SystemdSupervisor::write_unit` 改为常量脚本 + 位置参数，
> agent 执行模式下 Agent `install_policy` 校验路径只能是 `/etc/systemd/system/flame-proj-<id>.service`，
> 内容逐行比对 `render_unit` 的节 / 键白名单（ExecStart 可执行文件限 `/opt/flamepanel/`、`/usr/bin/`、
> `/usr/local/bin/`，拒绝 `+`/`-` 等执行前缀、shell 元字符、`..`、`LD_*` 环境变量与多余指令）；
> `rm -f` 同一路径与 `systemctl daemon-reload` 精确放行。

## 4. CI 安全门禁

| 检查 | 命令 | 门禁 |
|------|------|------|
| Rust 依赖审计 | `cargo audit` | 高危=0（否则阻断） |
| 前端依赖审计 | `npm audit --audit-level=high` | 高危=0（否则阻断） |
| 静态检查 | `cargo clippy --all-targets -- -D warnings` | 0 warning |
| 单元/集成 | `cargo test --all` | 0 fail |
| 前端类型/构建 | `npm run typecheck && npm run build` | 0 error |
| CSP 基线 | `npm run test:unit`（`csp.spec.ts`） | 哈希一致 / 三处同源 / 继承无漏 |
