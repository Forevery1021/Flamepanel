**最需要关注的三点**：

1. **数据库管理器存在 root 命令注入**（A-1 ~ A-3）：MySQL / Redis 的口令与配置值被拼进 `sh -c` 或 SQL 字符串，含单引号即可逃逸。已统一改为 argv 传参 + 转义 + 输入校验。
2. **应用商店安全扫描可被轻易绕过**（B-1）：旧实现对 compose 文本做子串匹配，`privileged:  true`（两个空格）、YAML 锚点合并、流式写法、`cap_add: [ALL]`、挂载 `/` 等都能过检。已改为结构化解析，高危项未确认即阻断。
3. **一键安装在 RHEL 系/Arch/Alpine 上基本不可用，在 Debian 上也常打开的是 nginx 欢迎页**（F-1 ~ F-6）：目录权限导致 403、`conf.d` 硬编码、Debian 默认站点抢占 80、SELinux 未处理、后端监听 `0.0.0.0` 绕过 nginx。已重写平台适配层，并用真实 `nginx -t` 做离线回归。

## 5. 架构层面的优化建议

以下为结构性建议，不影响现有功能，可按切片排入路线图：

1. **特权边界单一化**。当前存在三条特权路径：`sudo -n`（Embedded）、特权助手（Web 引擎）、Agent 白名单（远程）。三者的参数模型不同（argv / 精确 argv / 字符串），P-1 即源于此。建议以特权助手的「结构化请求 + 精确白名单 + 审计」为唯一模型：Embedded 非 root 时数据库/运行时/防火墙也经助手代办，Agent 复用同一协议结构。这也使「面板非 root 运行」下的数据库/运行时安装变得可用（Doc/10 当前注明不可用）。
2. **发行版差异集中到数据表**。本次已把包管理命令、包状态查询、Redis 布局收敛到 `infrastructure/os.rs`。后续 MySQL / PG / PHP 扩展名、Web 引擎包名建议同样以 `*_layout(distro)` 表驱动，避免 `match distro` 散落在 `webserver/`、`database/`、`runtime/` 各处（目前仍有 90+ 处）。长期可把 `DistroType` 扩成 `{family, id, version}` 结构体，消除 `Unknown(String)` 承载族标签的权宜写法。
3. **命令构造统一走安全原语**。`sh -c` 调用点应逐步清零：本次新增的 `append_line_command`、`mysql_escape_literal`、`validate_secret` 可作为规范写入 Doc/05，并加一条 CI grep 门禁（新增 `"sh", vec!["-c"` 需在白名单文件中）。
4. **应用商店信任模型分层**。扫描器负责「内容是否危险」，签名负责「来源是否可信」。建议在 `required` 签名策略下仍保留扫描阻断；并把扫描结果（结构化 findings）返回前端，替代纯文本错误，UI 可逐条展示并让用户逐条确认。
5. **前端**：代码健康度较好（无定时器泄漏、无 `console.log`、无 `any`；路由 30 处全部懒加载；echarts / xterm / vue-i18n 独立分包）。可改进：`SettingsView.vue`（1214 行）按 Tab 拆分为 `components/settings/*`（已有 Theme / DNS 两个先例；**v1.1 已拆出界面 / 关于 / 凭据（改密 + 2FA + JWT 轮换）三块，降至约 890 行**，剩余的常规 / 安全 / 备份三个表单分区共享脏状态与批量保存，暂留原处），并对 Tab 组件使用 `defineAsyncComponent` 进一步压缩设置页 chunk；`WebServersView.vue`（808 行）同理（**v1.1 已拆出「本机原生」页签 + 配套能力弹窗 `components/webserver/WebServerNativeTab.vue`，降至约 500 行**）。
6. **可观测**：`api_security_headers` 与 `request_id_middleware` 已形成中间件链，建议把审计日志、限流也统一注册到 `api/middleware.rs` 的有序列表并在 Doc/01 画出顺序，便于排查「头部重复 / 缺失」类问题。
