# 39 · R-01C 恢复资产与外部密钥清单

> 用户在 R-01B 后确认继续。本片提供只读的**恢复材料盘点**，不是自动备份、自动恢复、密钥匹配或生产身份验收。清单不内嵌任何秘密值。

## 1. 按源码核对的边界

SQLite 快照不是完整恢复包。以下路径是源码默认值或推导方式，不是对用户部署实际位置的断言；恢复前必须核对原服务的 WorkingDirectory、EnvironmentFile、环境覆盖和历史版本。

| 材料 | 源码依据 / 路径规则 | 丢失或变更的影响 |
| --- | --- | --- |
| 面板 SQLite 快照 | `config/loader.rs` 的 database.url、`lib.rs::new_with_backend` | 运行中的主库不可用普通复制替代一致快照；实际路径可能不是默认 data/app.db |
| 凭据加密主密钥 | `lib.rs::build_services` → `load_or_create_master_secret(Path::new("./data"))`，即 CWD/data/secret_encryption.key | 主密钥用于备份账号、DNS 账号、TOTP 和助手凭据。不是 JWT 密钥；丢失后重新生成不能解开旧密文 |
| JWT 签名密钥 | `config/loader.rs::load`；CWD/data/jwt_secret.key | 已存在的持久化密钥会覆盖 TOML / OP_JWT_SECRET 的有效值，避免轮换回退；保留或重新签发会话必须明确决策 |
| 节点注册 bootstrap | `config/loader.rs`；OP_BOOTSTRAP_TOKEN，否则 CWD/data/bootstrap_token.key | 用于节点注册，不等于每个已注册 Agent 的 AUTH_TOKEN；需要分别规划 |
| ACME 账户密钥 | `AcmeAccountKeyStore`；最终由 lib.rs 覆盖到**实际数据库父目录**下 acme/account.key | 账户连续性与续签材料，不能用 JWT / 凭据主密钥代替 |
| 证书与私钥 | `certificate_service.rs::write_cert_files`，实际数据库父目录/certs/<域名>/{fullchain.pem,privkey.pem}；记录还可持有其他经校验路径 | 私钥和证书文件不存放在证书记录行里；不能只恢复记录就认为 HTTPS 可用 |
| 面板入口 TLS | Doc/10 的安装 / Setup HTTPS 配置，或外部反向代理自备证书 | 未必有对应 certificates 记录，**不能仅靠该表行数判断是否需要保留** |
| 部署配置 | `config/app.toml`、服务 EnvironmentFile、OP_*、工作目录、UID、反向代理和 helper 配置 | 包含数据库地址、路径、端口及可能的秘密值；清单只检查文件元数据，不解析或回显 |
| 网站 / 项目 / 应用数据 | 数据库保存记录和路径；实际网站根、项目文件、Compose、绑定挂载 / 卷分别在文件系统或外部服务 | 记录数量不是文件完整性证明，不能从 DB 路径自动复制或访问宿主机 |
| 外部数据库与 Agent 材料 | 数据库管理记录、Agent config 中 AUTH_TOKEN / BOOTSTRAP_TOKEN 等 | 面板库不替代业务数据库备份、远端 Agent 配置、网络与凭据连续性 |

**重要路径差异**：凭据主密钥 / JWT / bootstrap 的默认位置依赖 CWD/data；ACME 与站点证书的最终位置依赖真实数据库父目录。这些不应被统一猜成“都在数据库旁边”。本片没有改变现有路径或生成策略。

## 2. 工具与输入契约

新增 `scripts/restore-drill/inventory.py`，Linux / Python 3.11+、标准库。它不启动内核或探针，不调用任何 `load_or_create_*`，不生成 / 轮换 / 修复密钥。

操作员先通过既有安全流程准备**独立暂存目录**与备份，再编写角色映射：

```bash
python3 scripts/restore-drill/inventory.py \
  --backup /secure/staging/snapshot.db \
  --assets-root /secure/staging/assets \
  --manifest /secure/staging/recovery-assets.json \
  --out ./new-unique-inventory-report
```

- `--assets-root` 必须是非符号链接目录，属主可读 / 遍历，group / other 无权限；推荐 0700。不要直接指向生产服务目录。
- `--manifest` 最大 64 KiB，只允许 `schema`、`jwt_strategy`、`assets`；assets 每条只允许 role / path，角色和路径不得重复。禁止内嵌密钥、token 或任意扩展字段。
- `path` 必须为暂存根目录内的规范相对路径：拒绝绝对路径、空组件、`.`、`..`、反斜杠和控制字符。每一级通过 dir_fd + O_NOFOLLOW 打开，拒绝中间 / 最终符号链接。
- 不按数据库里记录的任意路径去读宿主机；不递归搜索目录，不抓取网络，不自动解包。
- `--out` 必须不存在，生成 0700 私有目录和 0600 JSON / Markdown 报告；不覆盖旧报告。输入文件和声明资产不被修改。
- `--max-bytes` / `--timeout` 沿用离线复制上限和单调时钟检查；默认 512 MiB / 120 秒。系统文件操作仍不是硬实时限额。

模板：`scripts/restore-drill/recovery-assets.example.json`。模板含所有角色的**示例相对路径**，不是已存在的实际资产。按真实范围删除不适用的可选项；被声明但缺失的项也会阻断，不能拿空模板宣称准备完成。

## 3. 角色与策略

| role | 类型 | 自动要求 |
| --- | --- | --- |
| deployment_config | 文件，敏感 | 总是要求一份操作员准备的部署配置材料；只检查元数据，不验证内容覆盖全部配置 |
| encryption_master | 文件，敏感 | 已知字段存在 enc:* 引用，或密文扫描不完整时要求 |
| jwt_signing | 文件，敏感 | jwt_strategy=preserve 时要求 |
| bootstrap_token | 文件，敏感 | 观察到 nodes 记录时保守要求；环境来源也须先安全暂存，工具不读取进程环境 |
| acme_account | 文件，敏感 | 观察到非 uploaded / self_signed 来源证书时保守要求 |
| certificate_bundle | 目录，敏感 | certificates 有记录时要求；面板 / 外部代理 TLS 必须额外人工确认 |
| website_data / project_data / application_data | 目录 | 对应网站 / 项目 / 安装应用记录非空时要求 |
| external_database_backups / agent_material | 目录，敏感 | 对应数据库 / 节点记录非空时要求 |

`jwt_strategy` 必须显式选择：

- `preserve`：盘点已暂存的签名材料。存在不等于格式正确、身份连续或与生产实际生效密钥一致。
- `reissue`：仅记录“拟重新签发会话”的计划，报告新增待批准事项；工具**不会生成密钥、撤销 token 或改变任何会话**。这也不验证生产进程是否仍会被旧持久化文件覆盖。

敏感文件应为属主可读、group / other 无权限（通常 0600 / 0400）；空文件、硬链接、FIFO / 设备、类型不符、符号链接或不可读路径被拒绝。敏感目录只验证该目录权限，**不验证内部所有文件的权限、数量、映射或时点完整性**。

## 4. 数据库观测范围

只对隔离快照执行完整性 / 核心 schema 检查和固定白名单聚合 SQL，不返回字段原值或 DB 中的路径：

- backup_accounts.config_json
- dns_provider_accounts.credentials_json
- user_two_factor.secret / pending_secret
- panel_settings 中 key=assistant.api_key 的 value

对 `enc:*` 计数，未知版本不会静默当作明文。字段为非 TEXT 值时记录 coverage gap；旧表 / 列缺失也视为未覆盖，而不是“没有密文”。

资源观测仅含 websites、projects、installed_apps、databases、nodes、certificates 的行数及证书来源聚合。其他模块、未来字段、SQL 之外的秘密和部署覆盖均须人工复核。不会解析历史明文凭据或解密任何值。

## 5. 报告语义：不产生“恢复就绪”假象

输出 `inventory.json`（`flamepanel/recovery-inventory/v1`）与 `inventory.md`：

- `BLOCKED` / 退出 1：已观测必需材料缺失 / 不安全，已声明资产不可用，或输入 / 数据库检查失败。
- `REVIEW_REQUIRED` / 退出 0：已声明及已观测必需资产的元数据检查没有阻断项，但仍需人工复核。**不是 PASS，不是可启动生产的授权。**
- 退出 2：参数或报告输出失败。
- `restore_ready=false`、`key_match_verified=false`、`production_auth_verified=false` 始终保留。
- `secret_contents_read=false` 特指**没有读取被声明资产文件的秘密内容**：只 open + fstat，不 read、decode、hash、fingerprint 或复制。工具仍需读取用户提供的无秘密 manifest 和 SQLite 隔离副本；因此不要把秘密值放进 manifest。

即使文件内是错误密钥或只有空白字符，只要元数据满足条件，也只能记为 `PRESENT_UNVERIFIED`，不能证明密钥匹配。空目录同样不能证明里面有完整备份。报告包含固定角色、状态、聚合数量和数据库摘要，不包含资产路径、文件名、密钥长度 / 内容 / 指纹、用户数据或原始异常。

权限位检查不代替 ACL、属主 / service UID、挂载边界与最终恢复权限审核。扫描不会自动消除 manual_review 条目。

## 6. 回归与证据

```bash
python3 -m unittest discover -s scripts/restore-drill -v
cargo test --locked -p flame-kernel --no-default-features --features sqlite --test restore_assets
bash scripts/ci-local.sh --keep-going all
```

- 新 Python 用例覆盖缺失 / 空主密钥、错误格式但存在、密文扫描覆盖缺口、未知版本、非文本字段、资源依赖、JWT 决策、权限、符号链接 / 硬链接 / FIFO、目录不完整、拒绝覆盖与报告脱敏。
- Rust 集成使用真实 `run_migrations` 与 `SecretCipher` 生成密文：缺主密钥时 BLOCKED，提供**故意错误的密钥文件**后只能 REVIEW_REQUIRED、key_match_verified=false；数据库原字节保持不变。
- Python 用例由既有 `restore_drill` Rust 集成入口发现，新 Rust 用例也随现有 cargo test 门禁运行；不修改 CI / 云原生构建。
- `FP_INVENTORY_EVIDENCE` 可将合成集成场景报告导出到新证据目录；重复运行拒绝覆盖同名报告，完整门禁不沿用该变量。
