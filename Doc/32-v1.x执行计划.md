## 3. `fpctl` —— 面板命令行（对标 1pctl，面向脚本与 AI）

**定位**：部署了面板的主机上的本地运维入口。两类能力：

1. **离线运维**（面板进程未运行也可用，直接读 `config/app.toml` / `data/` / systemd）：状态、启停、重置密码、改端口、诊断、看日志；
2. **在线调用**（经本机回环调用 REST API，用 `data/jwt_secret.key` 现签 60 s 短期令牌，身份为指定管理员）：任意 API（`fpctl api GET /api/websites`），天然覆盖面板全部能力。

**AI 协同契约**（让 LLM Agent 能可靠驱动）：

- 所有命令支持 `--json`：stdout 只输出一个 JSON 文档，人类可读信息走 stderr；
- 退出码稳定：`0` 成功 · `1` 一般错误 · `2` 参数错误 · `3` 面板未运行 · `4` 权限不足 · `5` 资源不存在；
- `fpctl commands --json` 输出**机器可读的命令目录**（名称、参数、是否写操作、是否需要 root），供 AI 自我发现；M-AI-1 的 MCP Server 复用同一目录；
- 写操作支持 `--dry-run`（打印将执行的动作而不执行）；危险操作需 `--yes`。

| 命令                                                 | 说明                                                                     |
| ---------------------------------------------------- | ------------------------------------------------------------------------ |
| `fpctl status`                                       | 服务状态、版本、监听地址、健康检查、数据目录占用                         |
| `fpctl start \| stop \| restart`                     | 经 systemd 管理面板服务                                                  |
| `fpctl version`                                      | CLI 与面板版本                                                           |
| `fpctl info`                                         | 访问地址、管理员用户名、安装目录（不含密码）                             |
| `fpctl reset-password [--user U]`                    | 生成新随机密码（或 `--password-stdin`），写库并吊销该用户会话            |
| `fpctl port set <N>`                                 | 修改监听端口（写配置 + 可选重启 + 防火墙提示）                           |
| `fpctl logs [-f] [--level warn] [-n 100] [--grep S]` | 读内核日志文件（§4 同一格式）                                            |
| `fpctl log-level get \| set <level>`                 | 查看 / 在线修改内核日志级别                                              |
| `fpctl doctor`                                       | 诊断：端口占用、磁盘、数据库完整性、密钥文件权限、systemd 单元、时间同步 |
| `fpctl api <METHOD> <PATH> [-d JSON]`                | 以管理员身份调用任意 REST API                                            |
| `fpctl openapi`                                      | 输出 OpenAPI 文档                                                        |
| `fpctl backup create \| list`                        | 经 API 触发 / 列出备份                                                   |
| `fpctl upgrade [--version V] \| rollback`            | 见 §5                                                                    |
| `fpctl commands`                                     | 命令目录（AI 自我发现）                                                  |

实现：`flame-kernel/src/bin/fpctl.rs` + `src/cli/`（参数解析手写，不引入 clap——遵守「不加依赖」红线）；安装脚本把 `fpctl` 与 `flamepanel` 一同部署到 `/usr/local/bin/`。

## 4. 内核日志与错误反馈（W0）

**五级**：沿用 `tracing` 的 `TRACE < DEBUG < INFO < WARN < ERROR`，语义统一如下（Doc/05 同步）：

| 级别  | 何时使用                                                     | 默认是否落盘   |
| ----- | ------------------------------------------------------------ | -------------- |
| ERROR | 请求失败且需人工介入（5xx、后台任务失败、数据不一致、panic） | 是             |
| WARN  | 可自愈的异常或潜在风险（重试、降级、配置可疑、权限不足回退） | 是             |
| INFO  | 生命周期与业务关键事件（启动、迁移、任务完成、登录）         | 是（默认级别） |
| DEBUG | 排障细节（外部命令参数、缓存命中、分支判定）                 | 按需开启       |
| TRACE | 极细粒度（逐帧 / 逐行）                                      | 仅开发         |

**落盘**：`<工作目录>/logs/flamepanel.YYYY-MM-DD.log`（`OP_LOG_DIR` 可改），JSON Lines（每行一个对象：`timestamp` / `level` / `target` / `fields.message` / `span` 上下文含 `request_id`、`username`），按天切分 + 单文件 64 MB 滚动（`OP_LOG_MAX_FILE_MB`；`.1`、`.2`… 最多 20 个），默认保留 14 天（`OP_LOG_RETENTION_DAYS`）；panic 以 ERROR 记录位置与消息并额外写 `crash-<时间>.log`。控制台输出保持原样（`RUST_LOG_FORMAT=json` 仍有效）。

**运行时调级**：`PUT /api/kernel-logs/level`（`settings:update`）即时生效，重启后回到 `OP_LOG_LEVEL`（缺省 `info`）。

**错误反馈闭环**：5xx 响应对客户端仍脱敏（M9 不变），但前端在错误提示中附带响应头 `X-Request-Id`；面板「系统日志 → 内核日志」按请求编号搜索即可定位完整错误链。

**写入模型**：独立写线程 + 8192 行有界队列，请求线程只 `try_send`，满了丢弃并计数（概览 `dropped_lines`，面板告警），保证磁盘慢时不拖慢请求；Guard 在进程退出时排空队列并 flush。

**读取模型**：64 KB 反向分块读取实现「最新在前」分页，`before` 为字节偏移游标；单次最多扫 32 MB（过滤很严时分多页返回），计数超过 256 MB 只统计前段并标 `truncated`，结果按（文件名, 大小, 修改时间）缓存。

**面板**：系统日志页新增「内核日志」页签——文件选择、五级筛选（带计数）、关键字 / 请求编号搜索、实时追踪、行展开查看结构化字段、复制与下载；原「实时事件」页签保留。

## 5. 部署标准化（W1）

- **目录**（已交付，W1-b）：`/opt/flamepanel/{releases/<版本>/{bin,frontend}, current -> releases/<版本>, frontend -> current/frontend, data/, logs/, workspace/, backups/}`；`/usr/local/bin/{flamepanel,fpctl}` → `current/bin/*`。稳定路径不变，所以 systemd `ExecStart`、nginx `root` 与旧安装完全兼容；布局逻辑在 `cli/release.rs`，纯文件系统操作，单测覆盖。
- **收编**：`fpctl adopt`（幂等）把旧布局的普通文件移入 `releases/<flamepanel --version>`；`install.sh` 部署完成后自动调用（失败只告警），重跑 install.sh 时先摘链接再平铺写入、再收编为新版本。
- **升级**（已交付）：`fpctl upgrade`：下载（GH + 镜像，与 install.sh 同源）/ `--from-dir` → 强制 SHA-256 → 安全解包（仅普通文件与目录）→ 新二进制 `--version` 核对 → `VACUUM INTO` 备份库 → 原子切换 `current` → 重启 → 60 s 健康检查 + 版本核对，失败**自动回滚** → 按 `--keep` 清理（当前与上一个永不删）。`fpctl rollback` 切回 `releases/.previous`。
- **验收**：`tests/fpctl_release.rs`（旧布局 → adopt → 篡改校验和 / 含符号链接的包被拒且无残留 → 升级 + 备份 → 同版本无操作 → 回滚 → prune → 参数校验）。
- **未做（顺延）**：`config/flamepanel.env` 模板化生成（与 Doc/10 §5 同源）；Docker `x.y` 标签；面板内一键升级（服务受 `ProtectSystem=strict` 约束，须经特权辅助进程，列入 v1.1 评估）。

| 日志管道模式聚类                                       | 建立在 W0 的结构化日志之上 |
| IaC 导出（网站 / 数据库 / 应用 → 声明式 YAML）         | 纯读取 + 序列化            |

暂缓（需 ADR）：headscale 零信任、eBPF execve 审计、火焰图剖析、QUIC 节点通道、云商镜像矩阵、PR Preview 环境。

**M-E 首片决策（2026-10-09，#185）**：用户确认先做 IaC 只读配置导出。接口 `GET /api/iac/export`，版本化 YAML；入口 `settings:read`，各区块再检查对应资源读权限。配置字段采用白名单，明确排除凭据面 / 原始配置 / 关联 ID；不加导入、部署或 UI，先交付 API 与自动化回归。导出是配置清单而非完整恢复声明；其余 M-E 范围仍保留人工确认要求。

**M-AI-3**：LLM Provider 抽象（OpenAI 兼容协议 + Ollama），NL2API 以 OpenAPI 为工具目录，所有写操作走 M-AI-2 的 confirm 分级与审批；默认关闭，需管理员配置 Provider。

> **已交付（batch-7）**，实现要点：
>
> - **分层**：`domain::assistant`（配置 / 对话消息 / 历史校验，纯函数）→ `infrastructure::llm`（`LlmProvider` trait，OpenAI `/chat/completions` 与 Ollama `/api/chat` 两个实现，响应 ≤ 4 MiB）→ `application::assistant_service`（配置读写，API Key 经 `SecretCipher` 加密，接口只返回 `has_api_key`）→ `api::handler::assistant`（Agent 循环）。
> - **Agent 循环**：每轮最多 `max_steps`（1–12，默认 6）次模型调用、每步 ≤ 8 个工具调用；工具输出给模型 ≤ 16 KiB、给前端 ≤ 4 KiB；超步数返回 `step_limit_reached`。同一用户同一时刻只允许一个对话（否则 429）。服务端**不保存对话**，历史由前端携带（user / assistant 交替、以 user 结尾、≤ 40 条、单条 ≤ 32 KiB）。
> - **工具与边界**：`api_search` / `api_get` 只暴露 OpenAPI 中声明的 GET、且 `route_permission` 判定为读动作并被调用者角色允许的接口；拒绝名单覆盖认证 / 初始化、MCP 与助手自身、文件、设置、备份账号 / DNS 凭据 / 证书、下载 / 导出 / 流式、2FA 等；输出只接受 JSON 并统一脱敏。MCP 工具与 `/api/mcp` 共用同一闸门（`mcp::gate`），写 / 高危工具只生成审批单，由人在「审批」页签批准。
> - **身份**：助手以每用户内置凭证 `panel-assistant` 生成审批单（审计可区分来源）；该凭证被吊销后会在下次对话时重新签发——**要禁止某用户使用助手，应收回其角色的 `mcp:create`**，而不是吊销凭证。
> - **权限**：`GET /api/assistant/config` → `mcp:read`；`PUT /config`、`POST /test` → `settings:update`；`POST /chat` → `mcp:create`。
> - **Ollama 商店化**：内置应用新增 `ollama`（`ollama/ollama:0.12.3`，端口仅绑定 `127.0.0.1:11434`——Ollama 无鉴权，禁止直接暴露公网），与助手 Ollama Provider 的默认地址一致。

## 8. CNB 资源与稳定性测试（W2）

- **执行位置**：CNB 云原生开发环境（开发额度），**不占构建额度**、不进常规门禁；发版前（Doc/31 §8）与性能相关 PR 运行。原计划的 `perf-soak` 流水线（`api_trigger_perf`）因构建额度收紧取消（§9）。
- **入口**：`scripts/ci-local.sh perf`（完整 ≈ 45 min）/ `perf-quick`（≈ 5 min，时长 ×0.1）/ `just perf …`；环境内运行须挂 `cnb-workspace.sh hold` 保活（Doc/31 §5.3）。用法与判定细则见 Doc/06 §6.1。
- **流程**：`scripts/perf/run.sh` release 构建（与发布同配置：fat LTO）→ 临时目录起真实内核（SQLite，API 限流放开）→ `scripts/perf/load.py`（纯标准库 asyncio：HTTP keep-alive + 最小 WebSocket 客户端）经 setup API 建管理员 → 按权重轮询 15 个前端常用只读接口，并保持 `/ws/metrics` 推送连接 → 每 5 s 采样内核进程 RSS / CPU / fd / 线程。
- **场景**：idle 5 min（1 条 WS）→ load 10 min（200 HTTP 并发 + 20 WS，平均思考 0.5 s）→ soak 30 min（50 并发 + 5 WS，跨越 access token 15 min 过期：驱动定期续期，WS 被 token 复核断开后重连）。
- **判定**：idle RSS < 80 MB、soak RSS 斜率 < 1 MB / 10 min（稳态段最小二乘）、soak fd 增长 ≤ 20、错误率 0、进程存活、无 panic；报告附压测期间内核日志五级计数。
- **产物**：`perf-out/<quick-系数>/perf-report.{json,md}`、`kernel.log`、`kernel-logs/`；结论写入 CHANGELOG 与 §9。
