# 41 · R-01E-1 恢复证据预检与后续验收路线

## 2. 本片决策：先关联证据，不启动普通内核

新增 `scripts/restore-drill/preflight.py`，只打开操作员提供的 JSON 报告：

- 不接受数据库、资产目录、JWT/主密钥内容或二进制参数，不递归发现材料，不跟随报告内的路径。
- 不打开 SQLite、不启动子进程或服务，不读取配置环境，不执行迁移 / seed、撤销、签发或密钥生成。
- 复用 descriptor-relative / no-follow 路径规则，但不改变已有 A/B/C/D 工具的实现和默认行为。
- 对通过结构检查的报告比较**源快照 SHA-256 与字节数**；R-01C/D 的固定加密字段计数还必须一致。
- R-01B 的聚合计数来自迁移 / seed 后副本，不强行与迁移前抽样 / 元数据行数比较；相同输入摘要不等于每个阶段的数据没有变化。

**信任边界**：输入是未经签名、可被人工编辑的报告。一个结构合法的伪造报告仍可能通过一致性检查。本工具不独立打开源库验证摘要，也不鉴别生产者二进制或执行日志；不能作为自动启动/恢复的授权闸门。

## 3. 使用与输入契约

把同一源快照的报告放进操作员准备的私有目录，然后显式选择拟议 JWT 策略：

```bash
python3 scripts/restore-drill/preflight.py \
  --evidence-root /secure/staging/evidence \
  --drill-report drill/report.json \
  --inventory-report inventory/inventory.json \
  --keycheck-report keycheck/keycheck.json \
  --jwt-strategy preserve \
  --out /secure/reports/new-unique-preflight
```

- Linux / Python 3.11+、标准库；没有网络 / 二进制输入参数。
- 根目录非符号链接且属主可读/遍历、group/other 无权限（通常 0700）；报告是私有、单硬链接普通文件（通常 0600/0400），每个输入最大 128 KiB，最多三个输入。
- 输入路径必须为根内规范相对路径；拒绝绝对/遍历/空路径、控制字符、符号链接、FIFO/设备、重复路径、重复 JSON 键与未知 schema/字段。
- `--out` 必须不存在，父目录已准备；输出目录 0700、JSON/Markdown 0600，不覆盖输入或旧输出。期限默认 30 秒、最大 300 秒，不承诺文件系统硬实时隔离。
- 输入文件字节不变。只读取指定报告，不读取报告内引用的资产；报告输入本身不得内嵌秘密。
- `secret_contents_read=false` 特指本工具没有定位/读取资产秘密文件，不是“输入 JSON 不可能含敏感内容”的鉴定。不得把密钥文件冒充报告交给它。

### 3.1 必须满足的一致性

1. 演练为 `sqlite-with-dedicated-probe`，七阶段 PASS，迁移/HTTP/鉴权/写路由拒绝/正常停止标记齐全，未启动生产内核。
2. 盘点为 REVIEW_REQUIRED，已知扫描与资源覆盖无缺口；根据观测重新计算必需资产，不盲信 required 标记。材料仍只是 PRESENT_UNVERIFIED，不证明内容完整。
3. 所有参与报告的源摘要和大小一致。修改文件名、status 或同一处摘要不能替代完整关联。
4. 观察到加密引用时，密钥报告必需且必须为 MATCHED_WITHIN_SCOPE；固定字段计数一致，全部认证、零拒绝、无未知版本或覆盖缺口。
5. 没观察到已知加密引用时，不要求伪造一次密钥成功；可省略密钥报告。若提供，应是同源、零引用、未读密钥的 NO_SUPPORTED_CIPHERTEXT。不代表未来/未覆盖秘密不存在。
6. `--jwt-strategy` 必须与盘点中的 preserve/reissue 一致，但这只是下一片验证计划，**不是策略生效或会话撤销/重签发**。
7. 布尔必须是 JSON 布尔，计数不能是布尔/负数，时间不能是 NaN/Infinity；状态与计数矛盾、清理失败或输入中的生产就绪声称均拒绝。

旧 schema 覆盖不足会阻断本片，不自动迁移或“修复”报告；应先评审历史快照的升级/来源链，重新生成相应证据，不能混用迁移前后的不同快照摘要。

## 4. 输出：最多 REVIEW_REQUIRED，不是 PASS

输出 `preflight.json`，schema=`flamepanel/recovery-preflight/v1`，以及 `preflight.md`：

- `REVIEW_REQUIRED` / 退出 0：给定报告在本契约内一致，下一步仍需人工复核与独立批准。
- `BLOCKED` / 退出 1：缺失、不安全、矛盾或未通过的输入；后续检查保持 NOT_RUN，不自动补证据。
- 退出 2：参数或输出不可用，不回显输入值。

始终为 false：

- `restore_ready`、`production_auth_verified`、`key_match_verified`、`kernel_started`；
- `sessions_modified`、`keys_generated_or_rotated`、`database_opened`、`asset_secret_files_opened`；
- `report_authenticity_verified`、`freshness_verified`。

生产 RTO/RPO 始终未知。报告只输出固定检查结果、计划动作、共用源摘要/大小与引用数，不复制输入描述、错误、路径、凭据或原始异常。检查项中的 SCOPED_MATCH_REPORTED 是生产者声明的一致性，不是本工具自己解密的结果。

## 5. R-01E 身份验证拆片与停止边界

下列均为**后续待确认范围，不是本片已交付能力**：

| 顺序 | 范围与前置 | 退出条件 | 必须停止 / 不得顺带做 |
| --- | --- | --- | --- |
| E-2A · 身份加载 ADR 与合成契约 | 先审查 config/loader、utils/jwt、登录/会话/RBAC 路由；明确持久化 JWT 覆盖 OP_* / TOML 的规则 | 用合成用户/密钥验证正确、错误、过期、撤销和无权限；装配不启动后台业务 | 不读取生产 JWT，不改 token/密码/2FA/RBAC 格式或生成策略；需要新输入时再次确认 |
| E-2B · 操作员材料的可选验证 | E-2A 已验收；另行批准材料类型、只读暂存/授权管道与报告边界 | preserve 能解释有效密钥与历史会话关系；reissue 仅在明确批准的模拟材料上验证失效/重签 | 不因读取到 jwt 文件或密钥匹配就认为生产身份连续；不自动轮换、撤销或回写 |
| E-3 · 一个业务场景的只读验收 | 选已存在的少量业务读取/权限入口，声明 fixture、端口、拒绝路径 | 真正走权限实现，成功和越权拒绝都可重复，报告脱敏 | 不用管理员万能 token 替代 RBAC；不新增部署/导入或访问真实外部服务 |
| E-4 · 启动装配 / OS 隔离 ADR 后再试验 | 显式能力禁用清单、临时数据/密钥映射、网络/权限隔离、停止清理方案获批 | 恢复库有启用/过期待执行任务也不触发宿主动作，故障/超时/中断可回收 | 不在完整 Services 已启动后才打暂停标志；环境不支持隔离则阻断，不退回普通生产启动 |

### 5.1 preserve 与 reissue 的决策条件

- **preserve**：需证明实际有效签名材料、会话有效性/撤销状态和恢复身份一致；文件存在或临时探针鉴权不能代替。
- **reissue**：必须先决定会话/refresh token 撤销范围、用户再次认证路径、MCP/审批与 Agent 凭据是否独立。预检只记录计划，不生成新秘密或修改任何记录。
- 密码哈希、2FA、恢复码与主密钥解密属于不同契约；每项使用现有实现和合成负例，不把凭据可解密等同于凭据仍有效。

### 5.2 E-4 必审清单

恢复启动的迁移/seed 可改数据；WAF reload、定时任务、备份调度、证书续签、自动备份、指标清理、节点扫描、Outbox、通知与任务恢复都要逐项标注。先确定装配前禁用/替身端口与操作系统隔离，拒绝危险配置，而不是声称一个 bool 就能暂停一切。

不得自动增加特权容器/宿主挂载/网络白名单。涉及 CNB 镜像、云构建或真实系统资源时需单独授权；代码测试、隔离实验、真实系统验收、发布分别记录。

## 6. R-01F 外部资产与真实 RTO/RPO

在 E 阶段通过并获得真实环境授权后，再拆网站/项目文件、容器卷、外部数据库、证书私钥/ACME、入口 TLS、Agent 材料等范围：映射 UID/ACL/挂载、快照时点和外部依赖，不把目录存在或 DB 记录数量当作内容完整。

- 生产 RTO：明确故障/恢复开始点，到通过已批准认证、业务读取和必要外部依赖的 business-ready 点；单独记录存储复制/迁移/身份/业务阶段。
- RPO：需要可验证的业务提交水位与备份一致时点；不使用文件 mtime、备份年龄或 SQLite 完整性代替数据丢失窗口。
- 正常、损坏/摘要不符、空间耗尽、远端不可用、密钥/身份错误、外部材料不完整、取消/重启均须有失败证据。没有环境就保留未验证，不编造时间指标。

## 8. 本片回归入口

```bash
python3 -m unittest discover -s scripts/restore-drill -v
cargo test --locked -p flame-kernel --no-default-features --features sqlite --test restore_preflight
bash scripts/ci-local.sh --keep-going all
```

纯 Python 使用合成报告做合同与路径/权限/脱敏回归；Rust 用真实 BackupService 快照、专用探针、资产盘点与密钥匹配生成同源报告，再验证一致、混源、矛盾权限声称、策略冲突、缺失密钥证据和 reissue 计划。JWT 暂存内容故意只是占位材料，链路通过也不得标记生产身份就绪。

`FP_PREFLIGHT_EVIDENCE` 仅定点导出合成预检结果，必须是新的场景目录；完整门禁不沿用，以免覆盖旧证据。新用例通过既有 Python/Cargo 发现机制执行，不改 CI、镜像、依赖或门槛。
